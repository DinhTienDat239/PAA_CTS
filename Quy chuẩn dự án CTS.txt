================================================================================
        QUY CHUẨN DỰ ÁN CTS (Convert To SDK)  –  Spec for Agents
              Phiên bản: 1.2.0 | Cập nhật: 2026-05-13
================================================================================

Tài liệu này là spec đầy đủ giúp 1 agent mới (hoặc lập trình viên mới) có thể:
  (a) HIỂU đúng kiến trúc + công thức convert của dự án,
  (b) MỞ RỘNG thêm network mới đúng quy chuẩn,
  (c) CODE LẠI tool từ con số 0 mà vẫn ra output byte-perfect.

Đọc cùng tài liệu này (theo thứ tự ưu tiên giảm dần):
  1. công thức convert Mintegra.txt   – Spec chi tiết riêng cho MTG.
  2. CTS/README.md                    – Hướng dẫn end-user của CTS.
  3. MTGConverTool/README.md          – Hướng dẫn tool MTG độc lập (cũ).
  4. ALConvertTool/convert.py         – Source tham chiếu của AL gốc.
  5. GGConvertTool/main.py            – Source tham chiếu của GG gốc.


================================================================================
0.  THUẬT NGỮ (GLOSSARY)
================================================================================

  Luna Playable        : 1 file HTML chứa toàn bộ playable ad build bằng Luna
                          Labs Unity exporter. Thường ~2-3 MB / file.
  unityads             : "Target platform" mặc định khi build Luna playable.
                          Là input chuẩn cho mọi luồng convert của dự án.
  Mintegral / MTG      : Mạng quảng cáo mobile gốc Trung Quốc.
  AppLovin  / AL       : Mạng quảng cáo MAX của AppLovin.
  Google    / GG       : Quảng cáo Google (AdSense / AdMob playable).
  MRAID                : Mobile Rich Media Ad Interface – API chuẩn cho
                          playable ad trên hầu hết SDK (Unity Ads dùng MRAID).
  data-startup-only    : Attribute đánh dấu thẻ <script> chỉ chạy khi
                          playable khởi động. Luna dùng để gom các bundle.
  bundle               : 1 khối JS chứa data (sounds/jsons/blobs) đã nén bằng
                          decompressString / decompressArrayBuffer.
  byte-perfect         : Output trùng KHỚP từng byte với reference (kể cả
                          line endings, encoding). Đây là yêu cầu BẮT BUỘC
                          cho mọi network mà dự án hỗ trợ.

================================================================================
3.  CONTRACT CỦA 1 CONVERTER MODULE
================================================================================

Mỗi network X = 1 file `<x>_converter.py` trong `CTS/src/`. File phải tuân
thủ NGHIÊM NGẶT contract sau:

3.1.  EXPORT BẮT BUỘC
------------------------------------------------------------------------------
  • Hàm  `convert_html(input_path, output_dir, log=None, **kwargs) -> Result`
  • Dataclass  `<X>ConvertResult`  (dùng cho GUI hiển thị log).
  • (Tuỳ chọn) Exception  `<X>ConvertError(RuntimeError)`  – raise khi
    input không đủ điều kiện để convert. GUI sẽ bắt riêng exception này
    để show thông báo người dùng hiểu được.

3.2.  CHỮ KÝ HÀM convert_html
------------------------------------------------------------------------------
```python
def convert_html(
    input_path: str | os.PathLike,    # file HTML đầu vào
    output_dir: str | os.PathLike,    # thư mục output (TỰ TẠO nếu thiếu)
    log: Callable[[str], None] | None = None,
    # các tham số riêng của network (kwargs) – ví dụ output_filename
) -> XConvertResult:
    ...
```

3.3.  YÊU CẦU HÀNH VI
------------------------------------------------------------------------------
  a. PHẢI `output_dir.mkdir(parents=True, exist_ok=True)` trước khi ghi.
  b. PHẢI gọi `log(msg)` từng bước nếu `log is not None`.
       - Log đầu vào : "Đọc file input: <path>"
       - Log từng phép biến đổi: "  + <Mô tả>"
       - Log đầu ra : "Ghi output: <path> (<size> ký tự)"
  c. PHẢI trả về `Result` với ít nhất các field:
       - `output_html_path: Path | None`
       - `transforms_applied: list[str]`
       - `warnings: list[str]`
       - `input_size: int`
       - `output_html_size: int`
  d. NẾU input thiếu điều kiện bắt buộc -> raise `<X>ConvertError(msg)`.
     KHÔNG được nuốt lỗi và trả về Result rỗng.
  e. PHẢI có khối `if __name__ == '__main__':` cho CLI test, kèm
     `sys.stdout.reconfigure(encoding='utf-8')` để in tiếng Việt OK trên
     Windows console.

3.4.  BYTE-PERFECT OUTPUT
------------------------------------------------------------------------------
TUYỆT ĐỐI tuân thủ encoding + line ending của tool gốc tương ứng. Tham
khảo các quy tắc ở mục 6.

4.  CÔNG THỨC CONVERT CHI TIẾT TỪNG NETWORK
================================================================================

4.1.  NETWORK MTG  (Mintegral)
------------------------------------------------------------------------------
INPUT : 1 file HTML Luna Playable build cho `unityads`.
OUTPUT:
  output_dir/
  ├── mintegral.html
  └── assets/{scripts,jsons,blobs}.js
LINE  : CRLF (xem mục 6).

>>> Tham khảo SPEC ĐẦY ĐỦ ở file `công thức convert Mintegra.txt` <<<

Tóm tắt 5 phép biến đổi:

  TRANSFORM 1 — Tách 3 bundle `<script data-startup-only>` ra `assets/*.js`:
     Regex:  /<script data-startup-only>([\s\S]*?)<\/script>/
     Trong INPUT có TỚI 7 khối khớp regex, nhưng chỉ 3 là bundle thật.
     Phân loại theo HEAD của body (đã lstrip):
        • startswith("window.blobs")          -> assets/blobs.js
        • startswith("window.jsons")          -> assets/jsons.js
        • startswith("window._compressedAssets")
              VÀ chứa "_compressedAssets.push"
              VÀ chứa "decompressString"
                                              -> assets/scripts.js
        • Còn lại (startup/spector/brotli/base64) -> GIỮ NGUYÊN inline
     Khối được tách → thay bằng:
        <script src="assets/<tên>.js" defer data-startup-only></script>
     CHÚ Ý quan trọng:
        - 4 khối "startup-only" còn lại KHÔNG được động đến.
        - Nếu tách lầm 1 trong 4, output sẽ sai.

  TRANSFORM 2 — Xoá script remote-debug (console.re):
     Regex:  /<script>\(\(\)=>\{let e=window\.insertYourRemoteDebuggingTokenHere.*?<\/script>/
     Định vị bằng marker "insertYourRemoteDebuggingTokenHere".

  TRANSFORM 3 — Đổi `targetPlatform:"unityads"` -> `targetPlatform:"mintegral"`.
     Đúng 1 lần thay thế trong toàn file.

  TRANSFORM 4 — Đơn giản hoá `window.pi.apply(window,[]||[])` -> `window.pi.apply()`.

  TRANSFORM 5 — Thay 2 đoạn SDK adapter MRAID ở cuối <body> bằng template
     Mintegral. 4 chuỗi template nguyên văn ở `mintegra_converter.py`
     (hằng MRAID_VIEWABILITY_SCRIPT, MINTEGRAL_LIFECYCLE_SCRIPT,
     MRAID_INSTALL_SCRIPT, MINTEGRAL_INSTALL_SCRIPT).

Reference byte-perfect:
   Output/mintegral.html              -> 905.297  bytes
   Output/assets/scripts.js           -> 1.555.413 bytes
   Output/assets/jsons.js             -> 331.217  bytes
   Output/assets/blobs.js             -> 4.416    bytes


4.2.  NETWORK AL  (AppLovin)
------------------------------------------------------------------------------
INPUT : 1 file HTML Luna Playable (cùng input với MTG).
OUTPUT:
  output_dir/<basename_input>_AL.html      (1 file duy nhất, không assets)
LINE  : CRLF.

3 bước biến đổi (port nguyên văn từ `ALConvertTool/convert.py`):

  BƯỚC 1 — Quét toàn bộ `<script>...</script>` (regex DOTALL, IGNORECASE):
     Regex:  /<script\b[^>]*>.*?<\/script>/is
     XOÁ 2 loại script:
        a. Chứa chuỗi "insertYourRemoteDebugging"            (count_debug++)
        b. Có attribute "data-startup-only" VÀ tồn tại
           URL match `https?://` (case-insensitive)          (count_cdn++)
     ĐIỀU KIỆN BẮT BUỘC (giống tool gốc):
        count_debug ≥ 1 AND count_cdn ≥ 1
        Nếu vi phạm → raise ALConvertError(...) - KHÔNG ghi output.

  BƯỚC 2 — Strip URL hard-coded khắp file (5 phép replace tuần tự):
     1. "link"            -> ""
     2. 'link'            -> ''
     3. "https?://..."    -> ""        (re.IGNORECASE)
     4. 'https?://...'    -> ''        (re.IGNORECASE)
     5. href="..."        -> href=""   (re.IGNORECASE, áp dụng cho cả ')

  BƯỚC 3 — Ghi `<input.stem>_AL.html` vào output_dir.
     Encoding UTF-8, line endings CRLF (xem mục 6).


4.3.  NETWORK GG  (Google)
------------------------------------------------------------------------------
INPUT : KHÔNG phải file HTML gốc. Phải là `mintegral.html` (output của MTG).
OUTPUT:
  output_dir/
  ├── index.html                                  (đổi từ mintegral.html)
  └── assets/{scripts,jsons,blobs}.js             (COPY y nguyên từ MTG)
LINE  : CRLF.

DEPENDENCY:
  GG phụ thuộc MTG. Cấu hình ở `cts_tool.py`:
     NETWORK_DEPENDENCIES = {'GG': ['MTG']}
     NETWORK_ORDER        = ['AL', 'MTG', 'GG']   ← MTG luôn chạy trước GG
  Khi user tick GG mà chưa tick MTG → auto-tick MTG (trace BooleanVar).
  Khi MTG fail → GG raise GGConvertError("Thiếu output MTG…").

2 bước biến đổi (port nguyên văn từ `GGConvertTool/main.py`):

  BƯỚC 1 — Đổi `targetPlatform:"mintegral"` -> `targetPlatform:"google"`.
     Đếm số lần xuất hiện. Nếu = 0 → raise GGConvertError.
     Thay đúng 1 lần (lần đầu tiên).

  BƯỚC 2 — Thay 2 thẻ `<script>` CUỐI CÙNG bằng 2 template Google:
     Regex tìm:  /<script\b[^>]*>.*?<\/script>/is
     matches = tất cả match → lấy `matches[-1]` (cuối) và `matches[-2]` (kế cuối).
     PHẢI thay từ CUỐI lên trên (last trước, second-last sau) để span index
     của second-last vẫn còn hợp lệ.

     Template thay (lấy NGUYÊN VĂN từ `gg_converter.py`):
        NEW_SCRIPT_1 (thay second-last):
           '<script>window.addEventListener("DOMContentLoaded", (() => {
             window.devicePixelRatio = 2 })), window.addEventListener(
             "luna:build", (function () { window.pi.logLoaded(),
             window.dispatchEvent(new Event("luna:start")) }))</script>'
        NEW_SCRIPT_2 (thay last) – CHÚ Ý có 2 dấu cách đầu chuỗi:
           '  <script>window.addEventListener("luna:build", (() => {
             Bridge.ready((() => { Luna.Unity.Playable.InstallFullGame =
             function () { window.ExitApi.exit() } })) }))</script>'

     Nếu tổng số `<script>` < 2 → raise GGConvertError.

  BƯỚC 3 — Ghi `index.html` vào output_dir. KHÔNG đổi tên / xoá input như
     GG tool gốc (vì input của ta nằm ở folder MTG khác, không nên đụng).

  BƯỚC 4 (do GUI làm, không phải core) — Copy `assets/` từ MTG sang GG:
       shutil.copytree(mtg_assets_dir, output_dir / 'assets')
     Có thể delete dst_assets trước nếu đã tồn tại (idempotent).

Reference byte-perfect:
   GG tool gốc chạy trên Output/mintegral.html → index.html = 904.949 bytes.


4.4.  NETWORK META  (Meta / Facebook)
------------------------------------------------------------------------------
INPUT : 1 file HTML Luna Playable (cùng input với AL/MTG, build "unityads").
OUTPUT:
  output_dir/<basename_input>_Meta.html      (1 file duy nhất, không assets)
LINE  : CRLF.
DEPENDENCY: không.

3 bước biến đổi (đặc tả nguyên gốc từ user – không có tool legacy):

  BƯỚC 1 — Đổi targetPlatform "unityads" -> "facebook".
     html.replace('targetPlatform:"unityads"', 'targetPlatform:"facebook"', 1)
     Bắt buộc tìm thấy ≥ 1 match. Nếu 0 → raise MetaConvertError.

  BƯỚC 2 — Clean window.pi.apply(<bất kỳ args>) -> window.pi.apply().
     Regex:  /window\.pi\.apply\([^)]*\)/g  -> 'window.pi.apply()'
     Lý do dùng regex thay vì string compare: input có thể chứa biến thể
     `window.pi.apply(window,[]||[])` HOẶC `window.pi.apply()` rồi. Cả 2 đều
     được normalize về `window.pi.apply()`.

  BƯỚC 3 — Xoá 2 thẻ <script> cuối + thay bằng 1 template FACEBOOK_SCRIPT:
     Regex tìm:  /<script\b[^>]*>.*?</script>/is
     matches = tất cả match → lấy `matches[-1]` (cuối) và `matches[-2]` (kế cuối).
     Thay bằng:
        html[: matches[-2].start()] + FACEBOOK_SCRIPT + html[matches[-1].end():]
     (Gộp cả vùng giữa 2 script + cả 2 script thành 1 template duy nhất.)
     Bắt buộc len(matches) >= 2, nếu không → raise MetaConvertError.

     FACEBOOK_SCRIPT (lấy NGUYÊN VĂN từ `meta_converter.py`):
        <script>window.addEventListener("luna:build",(()=>{Bridge.ready((()=>{
        Luna.Unity.Playable.InstallFullGame=function(){
        "undefined"!=typeof FbPlayableAd?FbPlayableAd.onCTAClick():
        (console.warn("FbPlayableAd is not defined"),
        window.open(window.$environment.packageConfig.iosLink||
        window.$environment.packageConfig.androidLink,"_blank"))}}))})),
        window.addEventListener("open_ctalink",(()=>{FbPlayableAd.onCTAClick()})),
        window.addEventListener("luna:build",(()=>{window.pi.logLoaded(),
        window.dispatchEvent(new Event("luna:start"))}))</script>

  BƯỚC 4 — Ghi `<input.stem>_Meta.html` vào output_dir (UTF-8 no BOM, CRLF).

CHÚ Ý:
  • META KHÔNG xoá script remote-debug (`insertYourRemoteDebuggingTokenHere`).
    Spec hiện tại chỉ có 3 phép biến đổi ở trên, remote-debug giữ nguyên.
  • Output KHÔNG yêu cầu byte-perfect với tool nào (chưa có reference).
    Chỉ cần kiểm tra checklist ở mục 4.5 phía dưới.

================================================================================
5.  QUY CHUẨN ENCODING & LINE-ENDING (BYTE-PERFECT)
================================================================================

5.1.  Bảng line-ending cho TỪNG converter
------------------------------------------------------------------------------

  Converter   | Read input          | Write output
  ------------+---------------------+--------------------------------------
  MTG         | newline=''  (giữ)   | CRLF (normalize \n -> \r\n)
  AL          | default (universal) | CRLF (normalize \n -> \r\n)
  GG          | default (universal) | CRLF (normalize \n -> \r\n)
  META        | default (universal) | CRLF (normalize \n -> \r\n)
  MLC         | default (universal) | CRLF (normalize \n -> \r\n)
  Assets *.js | n/a (string trong RAM) | newline='' (không newline – body
                                          gốc không có line break)

5.2.  Kỹ thuật write CRLF byte-perfect
------------------------------------------------------------------------------
```python
content_out = content.replace('\r\n', '\n').replace('\n', '\r\n')
with output_html.open('wb') as f:        # binary write
    f.write(content_out.encode('utf-8')) # UTF-8 no BOM
```
LÝ DO 2 bước replace: nếu chuỗi đã có '\r\n' rồi (do input đã CRLF), bước
thứ 2 KHÔNG được biến nó thành '\r\r\n'. Vì vậy chuẩn hoá về '\n' trước.

5.3.  Encoding
------------------------------------------------------------------------------
  • Mọi file source code = UTF-8 (không BOM).
  • Mọi file HTML/JS output = UTF-8 (không BOM).
  • Tuyệt đối KHÔNG dùng `encoding='latin-1'` để decode input "cho chắc",
    trừ block fallback trong GG (đã có sẵn theo logic tool gốc).

6.  QUY CHUẨN GUI (cts_tool.py)
================================================================================

6.1.  Cấu hình network – ĐỘC NHẤT 3 BIẾN
------------------------------------------------------------------------------
```python
NETWORKS: list[tuple[str, str]] = [
    ('AL',   'AppLovin (...)'),
    ('MTG',  'Mintegral (...)'),
    ('GG',   'Google (...)'),
    ('META', 'Meta / Facebook (...)'),
    ('MLC',  'Moloco (...)'),
    # ('XX', 'mô tả network mới'),  ← thêm vào đây
]

NETWORK_DEPENDENCIES: dict[str, list[str]] = {
    'GG': ['MTG'],
    # 'YY': ['MTG'], ...
}
```

9.1.  Python

10.  CÁC ANTI-PATTERN PHẢI TRÁNH
================================================================================

  ✗ Đụng vào 4 khối `<script data-startup-only>` KHÔNG phải bundle
    (startup/spector/brotli/base64) khi convert MTG. Phải để inline.

    dùng `.*?` non-greedy + flag `re.DOTALL`.
  ✗ Write file output bằng `Path.write_text()` mặc định (Python sẽ
    translate LF nửa-vời, không byte-perfect). Luôn dùng `open('wb')`
    với binary để kiểm soát chính xác line ending.
  ✗ Hard-code đường dẫn tuyệt đối (vd. C:\Users\...). Luôn dùng relative
    path qua `Path(__file__).resolve().parent`.
  ✗ Chạy convert đồng bộ trên UI thread → app sẽ "Not Responding" 5–10 giây.
    Bắt buộc dùng thread.
  ✗ Để file `_test_*.py` lẫn trong `src/` khi build .exe (PyInstaller sẽ
    cố gắng đóng gói). Xoá trước build hoặc đặt ngoài `src/`.
  ✗ Bỏ qua `<X>ConvertError` ở GUI – luôn `except` riêng để báo lỗi
    người dùng-friendly.
  ✗ Đổi tên file output sang `<network>.html` mà không có lý do (mỗi
    network có convention riêng do tool gốc đặt ra):
      AL   : <basename>_AL.html
      MTG  : mintegral.html
      GG   : index.html
      META : <basename>_Meta.html
      MLC  : <basename>_MLC.html
  ✗ Sửa core converter để xoá / di chuyển file input (GG tool gốc có
    behavior này nhưng đã được loại bỏ trong CTS – KHÔNG khôi phục lại).
